=== Люди и Верблюды — Новости ===
Contributors: bfcamel
Requires at least: 7.1
Requires PHP: 7.4
Stable tag: 1.5.1

Редакционная система новостей фонда: визуальный Gutenberg/WYSIWYG-редактор, архив /news/, главная новость, предпросмотр, SEO и контроль готовности материала.


== Версия 1.5.1 ==

* Исправлен вывод HTML/JavaScript-счётчиков: код больше не оборачивается в дополнительные div-контейнеры плагина.
* Убраны служебные flex-стили, gap и padding, которые могли создавать пустой отступ перед подвалом даже у невидимого LiveInternet/Метрики.
* Сохранённый код счётчика выводится без изменения и в прежнем порядке; отключённые счётчики по-прежнему не выводятся.
* Вывод перенесён на поздний приоритет wp_footer, ближе к закрывающему тегу body.

== Версия 1.5.0 ==

== Версия 1.4.0 ==

Версия 1.4.0 — объединённый выпуск

Включает весь набор исправлений 1.3.1, перечисленный в RELEASE-NOTES-1.3.1.txt.

Редактор:
* Одна общая оценка готовности вместо повторных вычислений в нескольких панелях.
* Порядок работы обозначен как «Материал → Фото → Проверка → Предпросмотр → Публикация»; основные этапы панели пронумерованы.
* Состояние сохранения текста отделено от состояния SEO. Есть сообщения о конфликте и ошибке, повторная попытка сохранения SEO после ошибки.
* «Заполнить пустые SEO-поля» сохраняет ручные значения и соблюдает доступные пользователю права.
* Проверка размеров изображения обновляется вместе с данными медиа.
* Текст проверки готовности соответствует действию сервера: заголовки приводятся к H2/H3, рекомендации не блокируют публикацию.
* Переключатели предпросмотра подписаны по-русски.

Обновления и поддержка:
* Миграции старых схем выполняются фоновыми возобновляемыми пакетами до 25 новостей. Ошибка записи сохраняется в диагностике; завершение отмечается только после обработки всех пакетов.
* Активация поверх актуальной схемы 6 не запускает повторное массовое изменение SEO. Для перехода с 1.3.0 номер схемы не повышается.
* Страница диагностики показывает версии PHP/WordPress, прогресс обновления и ошибку, если она возникла.
* Логика блокировок, миграций и интеграции Rank Math вынесена в отдельные PHP-классы. Исходник редактора разбит на шесть последовательных частей с воспроизводимой сборкой без зависимостей.

Сохранение оформления:
* public.css, editor-content.css и editor.css побайтно совпадают с 1.3.0. Удаление накопленных CSS-переопределений сознательно не включено: требование владельца — сохранить отображение.
* Разметка главной, архива и отдельной новости сохранена. Изменены номер версии в data-атрибуте и атрибуты доступности главной фотографии: её alt теперь доступен экранным дикторам. Размеры, кадрирование, сетки, отступы, цвета и шрифты не изменены.
* Проверено сравнение HTML на одинаковых синтетических материалах в WordPress 7.1 / PHP 8.3; снимки экрана и фактическая тема/Elementor сайта в этой среде не проверены из-за недоступности проверки политики браузера.

Совместимость:
* Требования сохранены: WordPress 7.1+, PHP 7.4+.
* Интеграционные тесты выполнялись на WordPress 7.1, PHP 8.3.32 и Rank Math 1.0.278. Синтаксис PHP дополнительно проверен на 7.4.
* Версия Rank Math на рабочем сайте неизвестна; перед установкой нужна проверка на копии с его фактическими версиями темы и плагинов.


== Версия 1.3.1 ==

Версия 1.3.1 — исправления надёжности (включены в 1.4.0)

* Окончательный адрес новости проверяется на уникальность после транслитерации. Существующие опубликованные адреса автоматически не меняются.
* При активном Rank Math SEO сохраняется его собственным REST-обработчиком; LV News Suite не выполняет параллельную запись тех же полей при сохранении материала.
* Проверяются отдельные права general, advanced и social для SEO-полей. Локальные поля не позволяют обойти эти ограничения.
* Редактор передаёт исходный снимок SEO: устаревшая правка отклоняется с понятным сообщением. Одновременные записи сериализуются блокировкой.
* Изменение и очистка native Rank Math meta обновляют локальную резервную копию. После подтверждённого SEO-сохранения сохраняется ревизия, восстановление учитывает права.
* Проверки обязательных полей распространяются на планирование, серверные способы сохранения и публикацию по расписанию. Перед cron-публикацией неполная новость возвращается в черновик; опубликованные исторические материалы можно редактировать без принудительного заполнения новых полей.
* Без Rank Math отдельная новость использует свой SEO title; поисковое описание отделено от Open Graph description.
* Предпросмотр не открывает старую страницу при отклонённом или неуспешном автосохранении.
* Маршруты корректно учитывают установку WordPress в подкаталоге.


== Версия 1.3.0 ==

Исправлена интеграция с Rank Math:
* удалена ложная проверка по слишком рано зарегистрированным script handles; состояние определяется по настройке SEO Controls и реальному runtime Rank Math;
* редактор различает загрузку, готовность, отключённые SEO Controls, недостаточные права и ошибку загрузки;
* SEO title, description, focus keyword, canonical и Open Graph передаются напрямую в store `rank-math` через его штатные actions;
* изменения из собственной панели Rank Math зеркалируются обратно в поля LV News Suite без перезагрузки;
* Rank Math сам сохраняет свои dirty metadata через `rankmath/v1/updateMeta`, а серверная сверка LV News Suite остаётся страховкой от гонок запросов;
* кнопка пересчёта обновляет assessor и результаты Rank Math только после фактической готовности редактора;
* миграция схемы 6 повторно сводит существующие локальные SEO meta с данными Rank Math, отдавая приоритет уже заполненным значениям Rank Math.
* на `/news/` скрывается оставленный Elementor пустой абзац с неразрывным пробелом, поэтому перед подвалом больше нет белой полосы;
* HTML архивного и главного shortcode уплотняется перед выводом, чтобы поздний `wpautop` Elementor не вставлял `<br>` и лишние `<p>` внутрь карточек.

== Версия 1.2.8 ==

Исправления Rank Math, кадрирования и надёжности:
* LV News Suite больше не регистрирует чужие rank_math_* meta и не записывает/не удаляет rank_math_seo_score;
* синхронизация SEO сравнивает значения до и после REST-save: реально изменённая сторона побеждает, а при конфликте приоритет остаётся у собственной панели Rank Math;
* наличие плагина и доступность его редактора диагностируются отдельно; при выключенных SEO Controls редактор показывает честное предупреждение;
* официальный канал Rank Math по-прежнему получает текущий title/content, но SEO-поля зеркалируются после сохранения, без ложного обещания мгновенного score;
* публичные title, description, canonical и JSON-LD сохраняют ручные и расширенные значения Rank Math; схема NewsArticle дополняет, а не затирает его граф;
* масштаб, фокус и transform-origin изображения единообразно применяются в панели, карточке предпросмотра, архиве, главной и отдельной новости;
* CSS-переменные кадра защищены от конфликтов темы; при замене изображения кадр сбрасывается, а crop/SEO meta участвуют в autosave и revisions;
* клиентская и серверная готовность используют одинаковые 12 проверок;
* открытие уже актуальной новости больше не делает её «изменённой» только ради служебной записи score/version;
* стандартные типы новостей больше не создаются заново на каждом init, исправлена отложенная миграция rewrite rules, добавлен runtime-кеш повторных запросов;
* устранён вложенный HTML-элемент main, права записи meta проверяются для конкретной новости, обновлена системная диагностика.



== Версия 1.2.7 ==

Патч SEO-анализа и интеграции с Rank Math:
* подключён официальный Content Analysis API Rank Math через wp-hooks/rank-math-analyzer; анализатор получает актуальные title и content из текущего Gutenberg editor, а не старый снимок;
* при изменении SEO-полей старый rank_math_seo_score сбрасывается как устаревший и больше не продолжает показываться как будто он относится к новым данным;
* после сохранения сервер удаляет stale score, если SEO/title/excerpt/content изменились, а числовой балл остался ровно прежним; новый балл Rank Math при этом не подменяется и не рассчитывается самим LV News Suite;
* после изменения SEO, текста, заголовка и после завершения Save автоматически вызывается штатный rankMathEditor.refresh();
* автозаполнение больше не использует весь заголовок как focus keyword: формируется короткая естественная фраза 2–5 слов без начальных служебных слов;
* auto description при необходимости естественно включает фокусную фразу, что позволяет Rank Math корректно проверить точное вхождение;
* добавлен локальный SEO-чек-лист, который отдельно показывает заполненность/качество полей и не смешивается с собственным score Rank Math;
* ручные изменения в панели Rank Math и в панели LV News Suite синхронизируются в обе стороны через REST meta.

Важно: Rank Math оценивает не только факт заполнения полей. На итоговый балл также влияют вхождение ключевой фразы в текст/URL, длины полей, ссылки, изображения и другие тесты. Поэтому 100% редакционной готовности LV News Suite не обязаны означать 100/100 Rank Math.

* предпросмотр страницы с Desktop / Tablet / Mobile;

В «Новости → Все новости»:
* фотография, тип, статус главной и готовность;
* фильтры по типу и автору;
* «Сделать главной», «Дублировать», «Предпросмотр».

Совместимость:
* post type: lv_news;
* taxonomy: lv_news_type;
* shortcodes: [lv_home_news], [lv_news_archive];
* URL: /news/, /news/page/N/, /news/slug/;
* существующие записи не преобразуются в новый внутренний формат;
* Universal Hero и Hero Rotation остаются отдельными компонентами сайта.

== Обновление с 1.1.2 ==

1. Сделайте резервную копию файлов и БД.
2. В WordPress загрузите ZIP 1.3.0 поверх установленного плагина и подтвердите замену.
3. Убедитесь, что активен один плагин «Люди и Верблюды — Новости» версии 1.3.0.
4. Откройте «Новости → Система новостей»: версия схемы должна быть 6, версия маршрутов — 1.
5. Очистите кеш WordPress / Elementor / Autoptimize, если они используются.
6. Проверьте главную, /news/, одну старую новость и создание нового черновика.

== Важно ==

Версия 1.3.0 не требует ручной миграции содержимого старых новостей. При первом запуске схема 6 безопасно сверяет существующие SEO-поля с Rank Math; заполненные значения Rank Math имеют приоритет. Жёсткая проверка обязательных полей применяется только к первой публикации нового черновика; уже опубликованные материалы можно редактировать без принудительной переделки старого контента.
